# D03 요구사항 명세 — 누운 자세용 자동 책장 넘김 로봇

> D03 · 요구사항 명세 · 작성: 프로젝트 수행자(PM) · 검토: 수행자(QA), 지도교사 검토 예정 · 상태: 작성 · v0.5 · 관련: R-01~R-07 / T-01~T-12 · 스테이지: 02 Requirements

## ① 요구사항 계층 (Stakeholder → System → Subsystem)

| 계층 | 내용 |
|---|---|
| Stakeholder (사용자가 원하는 결과) | 누워서 책을 읽을 때 책을 손으로 들거나 종이를 잡지 않고, **버튼을 한 번 누를 때마다 오른쪽 종이책 책장 한 장을 왼쪽으로 넘긴다. 10회 입력해 총 10장을 순서대로 넘긴다.** |
| System (로봇 전체의 검증 기준) | 버튼 **10회 → 넘김 시도 10회**. 각 시도는 **정확히 1장 넘긴 경우만 성공**(0장 또는 2장 이상은 해당 시도 실패). 10회 중 **9회 이상** 한 장 넘김에 성공하고, 2장 이상 동시 넘김은 **0회**로 한다. 시도당 동작 종료 시간 **15.0초 이내**. 책 이탈 **0회**, 구동 범위 이탈 **0회**. |
| Subsystem (기능별 시간 목표) | 버튼 입력·작업 시작 **1초** + 오른쪽 롤러로 책장 분리·들기 **3초** + 얇은 막대로 왼쪽 이동 **8초** + 왼쪽 롤러로 정리·종료 **3초** = **15초/시도**. 책장은 자체 구동 장치 없이 롤러·막대와의 접촉으로 이동한다. |

**수치의 근거:** 실제 책은 여러 장(많게는 수백 장)으로 이루어져 있다. 하지만 수백 장을 모두 모델링하고 조작하기에는 시뮬레이션 구현 부담이 크므로, **여러 장을 순서대로 넘기는 기능을 확인할 수 있는 시범 범위로 10장**을 선택했다. 이는 실측 결과가 아닌 구현 범위에 대한 설계 판단이다. **9/10 성공**은 초기 평가를 위한 잠정 최소 합격 기준이며 최종 목표는 **10/10 성공**이다. **15초/시도** 및 세부 시간 배분도 실측 전 초기 설계 목표로 향후 시험에서 조정할 수 있다. 기존 D01 문제 정의의 사용 환경을 유지한다.

### '한 장'의 뜻과 판정 데이터

- 한 번의 명령을 처리한 뒤 오른쪽에서 왼쪽으로 넘어간 **물리적 종이 장수**를 기록한다. **`turned_pages = 1`만 해당 시도 성공**이며, `0`은 넘기지 못한 실패, `2` 이상은 여러 장을 함께 넘긴 실패이다.
- 10장 시도에는 실제로 구분되는 페이지가 필요하다. 현재의 **한 장짜리 MuJoCo 시제품**에서 동일한 한 장을 되풀이해 10번 넘겼다고 기록하면 **10장 연속 넘김 검증이 아니다**.
- `src/judge.py`는 MuJoCo 실험에서 측정한 값을 **판정만** 한다. 실제 책장 움직임을 만들어 내거나 자동으로 측정하지 않는다.

## ② 요구사항 명세표

| ID | 종류 | 요구사항 (측정 가능한 기준) | 우선 | 확인 | 숫자/조건의 근거 |
|---|---|---|---|---|---|
| R-01 | 기능 | 버튼 입력 **10회**에 대응하는 10회 시도 중 **9회 이상**에서 정확히 **한 장**을 오른쪽에서 왼쪽으로 넘긴다 (`sum(p == 1) >= 9`). 한 번에 **0장** 넘어간 시도는 실패로 센다. | Must | T-01, T-02, T-03, T-05 | 수백 장 전체 모델링은 어려우므로 연속 동작 검증을 위한 10장 시범 범위, 9/10은 잠정 합격선 |
| R-02 | 기능 | 한 번의 버튼 입력으로 **2장 이상 동시에 넘기는 경우는 0회**여야 한다 (`all(p <= 1)`). 이 조건만으로 0장을 성공으로 보지 않으며, 개별 성공은 반드시 `p == 1`이다. | Must | T-04, T-05 | 책장을 한 장씩 분리해야 하는 사용자 요구 |
| R-03 | 성능 | 모든 넘김 시도는 시작부터 종료/실패 확정까지 **15.0초 이내**에 마친다 (`max(elapsed_s) <= 15.0`). | Must | T-06, T-07 | 실측 전 초기 설계 목표 |
| R-04 | 기능 | 한 번의 시도가 종료되면 롤러와 넘김 막대를 기준 위치로 복귀시켜 다음 버튼 입력을 받을 수 있다. | Should | T-08 (후속 통합시험) | 10장 연속 조작을 위한 준비 상태 |
| R-05 | 안전 | 책 본체가 고정 장치에서 이탈하는 사건 **0회**, 롤러·막대가 정의된 구동 범위를 벗어난 사건 **0회**여야 한다 (`book_falls == 0`, `joint_limit_violations == 0`). | 안전 | T-09, T-10 | 책 추락·기계 무리 방지 |
| R-06 | 운영 | 시험 1회마다 시도 10개의 결과·소요시간(s)·이탈 사건 수·합격 여부를 `logs/results.csv`에 **기록 1행**으로 남긴다. | Should | T-11 (후속 통합시험) | 반복 평가와 진행 기록 |
| R-07 | 설계 | **책장 자체에 연결한 구동 액추에이터는 0개**이고, 롤러와 막대의 접촉으로만 책장을 이동시킨다. | 안전/설계 | T-12 (장면 구조 검사 예정) | 프로젝트의 물리적 책장 조작 방식 |

**MoSCoW:** Must는 R-01~R-03 세 개만 지정한다. Should는 여력이 되면 구현한다. 안전(R-05·R-07)은 우선순위 개수에 포함하지 않고 항상 점검한다. MuJoCo의 물체 관통·수치적 불안정성은 제품 기능 요구가 아니므로 **이 명세표에 포함하지 않고 개발 단계의 장면 디버깅/품질 점검에서 별도 관리한다.**

### 범위 밖 (Won't: 이번 프로젝트에서는 안 함)

- 실물 기계 제작·실사용 안전 인증, 얼굴 위 실제 로봇 가동
- 모든 책 크기·종이 두께에 대한 범용 대응
- 음성 제어, OCR, 화면 표시·원격 제어, 양방향 자동 넘김
- 복잡한 형태의 책이나 10장 초과 분량에 대한 신뢰성 보장

## 판정 함수의 입출력

```python
judge_episode(
    turned_pages=[1] * 10,             # 입력마다 실제 넘어간 장수, 총 10개
    elapsed_s=[12.0] * 10,             # 입력마다 종료까지의 시간(초), 총 10개
    book_falls=0,                       # 책 본체 이탈 사건 수
    joint_limit_violations=0,          # 구동 범위 이탈 사건 수
)  # -> True / False
```

- 입력 10개가 정확히 있어야 하며, 정수 장수·유한하고 음수가 아닌 시간만 허용한다.
- 안전 조건 R-05는 함께 판정하지만, MuJoCo 물리 계산 오류는 **이 함수의 판정 대상이 아니다**. 개발 과정에서 별도로 점검한다.
- 구조 요구사항 R-07도 결과만으로 판단할 수 없어 4일차 MJCF 액추에이터 정의를 점검한다.

### 아직 완료되지 않은 검증

- 판정 코드의 단위 테스트가 통과해도, **MuJoCo에서 종이 10장을 실제로 넘긴 것은 아니다**.
- '한 장이 완전히 넘어갔다'의 공간 좌표·접촉 조건과 책 추락/구동 범위 이벤트의 수집 방법은 4~5일차에 정의한다.
- 실물에서 생길 수 있는 **찢김·끼임·손가락 접촉 위험**은 후속 안전 검토 대상이다. 물리 모델에 없으면 이 문서에서 자동 검증했다고 주장하지 않는다.
