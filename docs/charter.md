# D02 팀 차터 — 자동 책장 넘김 로봇 (1인 프로젝트)

> D02 · 팀 차터 · 작성: 프로젝트 수행자(이름 기입) · 검토: 본인 자체 검토 / 지도교사 검토 예정 · 상태: 작성 · v1.0 · 스테이지: 01 Discovery

## 목표 한 줄

누워서 독서하는 사람이 책을 손으로 지탱하거나 직접 책장을 넘기지 않아도 되도록, 책을 공중에 지지하고 버튼 입력으로 책장 한 장을 넘기는 로봇을 MuJoCo 시뮬레이션으로 구현·검증한다.

## 범위

| 구분 | 내용 |
|---|---|
| 한다(In) | 공중에서 펼친 책을 지지하는 프레임 모델링; 유연한 페이지 1장 모델링; 오른쪽 분리 롤러·상단 넘김 막대·왼쪽 받침 롤러 구성; 버튼 입력에 따른 작동 순서; 접촉 기반 넘김 실험; 성공·실패 기록 |
| 안 한다(Out) | 실물 로봇 제작; 음성 인식; 전자책 기능; 모든 크기·재질의 책 대응; 처음부터 여러 장을 안정적으로 분리하는 기능 보장 |

※ 여러 장 넘기기는 한 장 넘기기 검증 후 확장 과제로 둔다. 페이지에는 넘김을 직접 지시하는 구동 모터를 장착하지 않는다.

## 플랫폼 결정

- **플랫폼:** Python + MuJoCo (MJCF XML 장면 및 물리 시뮬레이션)
- **선택:** 새 물리 엔진을 만들지 않고 MuJoCo의 관절·접촉 기능과 `flexcomp` 변형체 예제를 활용한다.
- **근거:** 롤러와 막대가 페이지에 접촉해 움직이는지 실험하려면 물리 시뮬레이션이 필요하다.
- **기술 위험:** 얇은 페이지의 변형·접촉이 불안정할 수 있다. 1차로 페이지 1장과 롤러 1개부터 검증하고, 어려우면 여러 강체 조각을 연결한 페이지로 단순화한다.

## 일하는 방식

- 매 작업일 **한 일 / 막힌 일 / 다음 할 일**을 `logs/progress.md`에 기록한다.
- 설계 결정이 바뀌면 근거와 영향을 문서에 남긴다. 1인 프로젝트이므로 의사결정자는 본인이다.
- 새 코드는 작은 단위로 실행·확인한 뒤 Git에 커밋한다. 실패도 오류 메시지와 함께 기록한다.
- 문서 상태는 **작성 → 검토 → 승인** 순으로 관리하며, 지도교사 검토 전에는 임의로 승인을 표시하지 않는다.
- 저장소 주소: **[GitHub 저장소를 만든 후 실제 URL 입력]**

## 완료 기준(1차 목표)

- MuJoCo 장면에 책 지지대·페이지 1장·롤러·막대가 표시된다.
- 버튼을 누르면 롤러와 막대가 순서대로 작동한다.
- **페이지 자체를 직접 회전시키는 제어 없이**, 로봇 장치와의 접촉에 의한 페이지 이동이 관찰되고 결과가 기록된다.

※ 정량 성공 기준은 3일차 D03에서 정한다.
